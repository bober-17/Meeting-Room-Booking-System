# Room Booking Service

Сервис бронирования переговорок. Администраторы создают переговорки и расписания, система формирует слоты для бронирования. Сотрудники просматривают свободные слоты и управляют своими бронями.

## Quick Start

```bash
docker-compose up --build
```

Сервис доступен на `http://localhost:8080`.

Все переменные окружения имеют дефолтные значения — дополнительная настройка не требуется. Для переопределения создайте `.env` в корне проекта (пример: `.env.example`).

## API

Полная спецификация: [`api.yaml`](api.yaml)

### Служебные

| Метод | Путь | Роль | Описание |
|-------|------|------|----------|
| GET | `/_info` | — | Health check, всегда возвращает 200 |

### Auth

| Метод | Путь | Роль | Описание |
|-------|------|------|----------|
| POST | `/dummyLogin` | — | Получить тестовый JWT по роли (admin / user) |
| POST | `/register` | — | Регистрация по email и паролю *(доп. задание)* |
| POST | `/login` | — | Авторизация по email и паролю *(доп. задание)* |

### Переговорки

| Метод | Путь | Роль | Описание |
|-------|------|------|----------|
| GET | `/rooms/list` | admin, user | Список переговорок |
| POST | `/rooms/create` | admin | Создать переговорку |

### Расписания

| Метод | Путь | Роль | Описание |
|-------|------|------|----------|
| POST | `/rooms/{roomId}/schedule/create` | admin | Создать расписание переговорки |

### Слоты

| Метод | Путь | Роль | Описание |
|-------|------|------|----------|
| GET | `/rooms/{roomId}/slots/list?date=YYYY-MM-DD` | admin, user | Доступные слоты по переговорке и дате |

### Брони

| Метод | Путь | Роль | Описание |
|-------|------|------|----------|
| POST | `/bookings/create` | user | Создать бронь на слот |
| GET | `/bookings/list` | admin | Все брони с пагинацией |
| GET | `/bookings/my` | user | Мои активные брони (только будущие слоты) |
| POST | `/bookings/{bookingId}/cancel` | user | Отменить бронь |

## Авторизация

Все эндпоинты кроме `/_info`, `/dummyLogin`, `/register`, `/login` требуют JWT в заголовке:

```
Authorization: Bearer <token>
```

Для получения токена используйте `/dummyLogin`:

```bash
curl -X POST http://localhost:8080/dummyLogin \
  -H "Content-Type: application/json" \
  -d '{"role": "admin"}'
```

`/dummyLogin` возвращает фиксированный UUID для каждой роли, что позволяет стабильно тестировать сценарии с проверкой владельца брони.

## Архитектурные решения

### Стратегия формирования слотов

Слоты формируются **при запросе** списка доступных слотов по переговорке и дате (`GET /rooms/{roomId}/slots/list?date=`), а не заранее.

Такой подход выбран по следующим причинам:
- Не требует фонового процесса или планировщика.
- Хранятся только слоты на фактически запрошенные даты.
- UUID слотов стабильны: повторный запрос той же даты возвращает те же идентификаторы.

Альтернатива — скользящее окно (заранее генерировать слоты на N дней вперёд через планировщик) — сложнее в эксплуатации и не даёт преимуществ при данных объёмах.

### Поведение при сбое Conference Service

При создании брони с `createConferenceLink: true` система:
1. Создаёт бронь в БД.
2. Запрашивает ссылку у Conference Service.
3. При успехе — сохраняет ссылку в брони и возвращает её клиенту.
4. При ошибке Conference Service — логирует её, возвращает бронь без ссылки (бронь не откатывается).

Бронь важнее ссылки на конференцию. Откатывать успешно созданную бронь из-за сбоя внешнего сервиса — плохой вариант (получается, что наш сервис зависит от Conference Service и перестает функционировать при проблеме в Conference Service).
